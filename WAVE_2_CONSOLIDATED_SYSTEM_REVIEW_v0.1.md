# Consolidated Wave-2 System Review v0.1

**Governed outcome: WAVE_2_PASS_WITH_BOUNDED_CORRECTIONS.** Review date: 2026-09-29. This is an architectural recommendation for ChatGPT review, not Golden Reference acceptance, candidate promotion, Gate 8 closure or System v1.0 freeze. Production, frozen contracts and registry statuses have not been changed by this review.

The three references demonstrate a credible reusable learning architecture: bounded perspective interpretation, authored repair under a constraint, and evidence-informed decision adaptation. Their completion models are materially different. The common state service is actually reused by two activity models, and GR06's opt-in layout extensions preserve GR04/GR05 defaults. However, this is **demonstrated prototype reuse within HRBA**, not validated cross-course production readiness or evidence of learner transfer. Generic registry validation has reproducible holes; candidate interfaces retain case assumptions; GR05 has visible encoding defects; GR05/06 risk visual and authoring monotony; GR06 still lacks required direct and independent semantic validation.

## Reuse versus duplication and taxonomy audit

**Healthy reuse:** one token/foundation/shell layer; work-artifact text fields, rubric controls and comparison conventions reused by the ledger; one storage service with activity-supplied validators and distinct identities; explicit opt-in template/composition extensions. The GR06 compatibility tests compare GR05's default DOM and settled PNG bytes. GR04 default CSS/HTML is preserved. These are observable reuse claims, not just matching registry names.

**Legitimate specialization:** keep INT-BUILD-REPAIR-01 and INT-EVIDENCE-DECISION-01 separate. Repair requires diagnosis, a weak original, two review rounds and connected feasibility repair; evidence decision requires typed informing/limiting links, an unresolved alternative, four routes and an evidence update. Likewise keep the two artifact blocks' semantic records distinct. Do not collapse them into an arbitrary schema-driven form engine merely to reduce object count.

**Accidental duplication:** both controllers assemble nearly the same saving/consent/receipt/recovery-choice and export-action UI; both compositions repeat workspace/stage/reference/action layout rules. UI-SAVE-STATE-01 is largely presentation CSS rather than a reusable receipt/consent view. Consolidate these small responsibilities when the next workspace consumes them, using callback interfaces and exact GR05/06 regression fences. Do not centralize completion logic with the saving UI. Shared normalization/T helpers are small duplication; extract only with a stable contract and tests, not a universal learning reducer.

**Ownership debt:** `node`, `writingField` and `rubric` are generic UI primitives physically housed in BLK-WORK-ARTIFACT-01; TPL-DEEP-WORKSPACE-01 imports the block's `node`. This introduces a lower-level UI dependency on a semantic artifact block. The ledger correctly owns source-note/source-metadata rendering after its final ownership refactor. Both interactions still assemble stage-specific views; acceptable controller coordination should be explicitly distinguished from owning layout. GR03's interaction relocates panels and manages collision fallback, mixing responsive arrangement with interaction/focus maintenance. Keep synchronized behavior, but document the composition/interaction adapter boundary before generalized reuse.

**Hard-coded scope:** BLK-PERSPECTIVE-01 permits 2–4 items, while its interaction says “all three” and uses document-global selectors/single Continue IDs. GR05's model reads generic field definitions but hard-codes `participation`, `accountability`, `evidence` for connected revision; its controller contains HRBA labels/export filename. GR06 has case-contract maxima as literals in parts of its model/view. TPL-DEEP-WORKSPACE-01 silently uses its repair default for an unrecognized configuration variant. These work for the frozen cases; they do not demonstrate unrestricted configuration. Before another consumer, either validate an explicit supported contract or make semantic role mappings/limits/labels configuration while preserving approved defaults. Arbitrary unknown variants must fail closed.

## State, revision and retention policy

The coherent shared rule is now **automatic active-session recovery for authored work; explicit opt-in for durable device retention; truthful degradation; learning completion independent of either**. GR05 and GR06 supply different validated payloads to one unchanged service. Identity, schema/contract/case versions, immutable first records and revision-bound acknowledgments distinguish retained work from stored completion flags. Restore validates and recomputes; it is not a trust boundary for certification or tamper-proof assessment.

The service handles divergent tiers, corrupt records, concurrent writers, explicit selection/fork, draft-only clear and failed deletion without claiming success. Session storage is not guaranteed erasure on browser closure; browser restoration and shared-device risk are disclosed. Clipboard/download are fallback output mechanisms, not proof that a file was safely retained. No cloud sync, collaborative editing, authenticated assessment authority or cross-device portability is demonstrated.

**GR03 recommendation:** retain its nonpersistent state as an explicit, grandfathered transient-interaction exception to its frozen contract. Its short bounded selected-response task does not justify a retroactive failure or local persistence patch. The older [observation](docs/GR03_REFRESH_PERSISTENCE_OBSERVATION.md) saying global recovery was unspecified is historical: G05-03 now establishes a rule for authored work, not an automatic retrospective requirement for every lens interaction. Before GR03 is used in a resumable course/portfolio or as assessed prerequisite evidence, authorize a shared adapter defining visited/selection/submission/feedback flags, preview-state isolation, restore invalidation and clear. Its `?state=complete` preview must never become credential evidence.

## Learning depth, progression and experience differentiation

The progression is credible at capability level: **interpret a bounded situation → construct and repair professional work → reason under mixed evidence and adapt a decision**. Reused ideas—evidence limits, explicit responsibility, preserved work and revision—connect the references. There is no implemented curricular transfer of GR03 work into GR05 or GR05 work into GR06; deliberate non-import of GR05 state is correct. Do not call these an integrated assessment chain yet.

Revision is genuinely represented: GR05 changes linked fields under C01; GR06 permits retaining a route while changing interpretation and follow-up after U01. Uncertainty and unresolved actions remain visible rather than forcing all-positive reviews. Consequences remain **documented or simulated**, not enacted project outcomes. Needed next: synthesis across an artifact bundle, externally accountable assessment/readiness decisions, transfer to the learner's context, later verification, safe peer response and an ecosystem handoff.

Writing burden is a real design risk even without word minima. GR06 asks for five source notes, two claim/limitation pairs, six decision fields, update/rationale and four criterion reviews with follow-up; GR05 similarly repeats artifact and review work. T prevents trivial emptiness but neither imposes nor proves depth. Preserve purposeful authoring in these patterns; do not make every next experience another long form. Future gate/assessment work should emphasize structured evidence mapping, comparison, prioritization, branching and concise decision rationale; portfolio work should emphasize revisiting artifacts and response, not retyping them. Representative learner usability/effectiveness evaluation remains deferred course-design work, not inferable from synthetic fixtures.

Visual observations are based on existing desktop/mobile/stress evidence, with [derived review crops](tests/wave2-review/) of unchanged screenshots. At 1440px the inspected GR03 initial capture is 1,311px tall, GR05 draft capture 4,842px and GR06 adaptation capture 8,695px. These are different stages/content, **not a controlled usability ranking**, but they make scroll/density exposure concrete. On mobile the reference-first stack and repeated evidence in link groups increase navigation distance. Paired per-field comparisons are accessible and useful; repeating every unchanged field equally can obscure the few decisions that changed. Any future summaries or changed-field emphasis must preserve access to complete text and be separately authorized.

GR03's illustration/lenses provide a different hierarchy and interaction rhythm. GR05's original/repair is appropriate for a document studio. GR06's sources/uncertainty/U01 deserve a recognizable evidence-led rhythm even though no new artwork is warranted. Current semantic differences exceed their visual differences. Before another reference is frozen, require an experience-differentiation brief stating what the learner sees/does next, density/scroll expectations and the reason for each region. Do not resolve monotony with decorative cards, arbitrary illustrations or new tokens.

## Deterministic AI production readiness

Canonical template references are now `{id, variant?}` with transitional string support; the schema reconciliation is accepted and **not reopened**. GR02's legacy string is intentionally accepted. Exact locked rebuilds and local generators establish repeatability for selected builds; two independently implemented AI builds of GR03/05/06 have **not** been shown materially equivalent.

A concrete validator gap remains distinct from the resolved template representation issue. `validate_spec` enforces schema and template ID/variant, while full component/composition/pattern ID checks are applied to locked GR01/04 paths, not all ordinary GR specs. Isolated temporary-copy probes accepted unknown GR06 component, composition, primary/supporting pattern, composition variant and build mode; an unknown template correctly failed. Current real specs resolve in a separate review check, so this is a **prevention gap**, not evidence that today's GR06 spec uses those unknown IDs. The GR03 frozen contract also names `UI-NAV-CONTROLS-01` while the registry/spec use shell-owned navigation; this needs an explicit dependency/alias decision, not invented registration.

Required controls before unrestricted builds: full registry cross-reference/variant validation for every spec and frozen-contract object list; reject unknown build modes and variants; define permitted candidate statuses and registry/manifest parity; machine-validated field/state contracts or generated drift assertions; explicit supported configuration and dependency manifests; current authority/status index with historical supersession; no preview completion in assessment; negative semantic fixtures and human sign-off distinct from structural tests. Preserve resource-first classifications and System Gap escalation rather than treating external catalog IDs as local authority.

Before Gate 8 final review, run independent duplicate builds from immutable packages **without using the reference implementation as an answer source**, and compare learning flow, outputs, predicates, accessibility/resilience and visual hierarchy under a declared material-equivalence rubric. Pixel equality is appropriate for locked unchanged defaults; it is not by itself an equivalence test for constrained independent builds.
