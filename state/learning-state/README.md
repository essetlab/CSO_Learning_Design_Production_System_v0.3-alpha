# SVC-LEARNING-STATE-01

Status: **PROTOTYPE**.

Generic two-tier storage, envelope validation, receipts, conflict choices, clear and serialization. Never grants completion.

Authorized by GR-05 revision 2 freeze. No Golden Reference acceptance or object promotion.

`createLearningState({identity, validatePayload, onReceipt})` accepts an activity-owned validator and emits separate session/device receipts. `save(payload)` serializes a clone synchronously to the active session and queues an opted-in device write under a Web Lock. A browser lacking Web Locks cannot promise safe device saving; session recovery and live work remain separate.

Envelope schema version 1 binds activity, contract version/revision and case version, draft ID, writer, sequence, unique revision stamp, device baseline, consent and caller payload. The service validates the envelope and calls the activity validator. The interaction then restores/recomputes its own learning predicates. No stored completion bit is trusted or generated by this service.

`initialize`, `resume`, `recoverSession`, `keepLocal`, `refreshChoices` and `discardIncompatible` preserve conflicting/corrupt records until explicit choices. Device-only drafts require explicit resume. A local fork gets a new ID and opts out. `disableDevice` and `clear` stop pending writes and compare versions before deleting; failures are visible. Automatic session recovery is not a secrecy guarantee when a browser restores an entire session after closure; the interface explains this and offers clear.

`downloadText` and `copyText` expose generic retention adapters; the artifact block owns every character and section of its representation. Only the shared service calls browser storage APIs. No cross-course validation or production promotion is claimed.
